# 0002：版本路线与验收门禁

## 定位

psi6 是面向 AI Agent 的 Python 桌面应用 SDK：统一的应用运行时、设计系统、后台任务，加上**可机器验证的开发规范**。最后一条把它和「带主题的 PySide6 封装」区分开。

## 原则

- 不做 PySide6 的第二套封装。Qt 已经提供的窗口、控件、模型视图和事件系统，不另起同义包装类。
- Agent-first 不是附带一份 Skill。组件要能被发现，规范要能被机械检查，示例要能被执行，错误要能被暴露。
- 每项能力由真实应用验证。发布门禁包含真实应用，不只看仓库内示例。
- 不引入大型服务框架、远程任务调度、DAG 引擎、自定义渲染系统。真实应用提出共同需求时再评估。

## 路线

### 0.4.1：设计系统收尾

调色板重调，新增 `Mono` / `Obsidian` / `Pine` / `ModernDark` / `CompactDark` 内置主题。勾选框与单选框指示器补全，QSS 图标改逻辑尺寸 SVG。150% 缩放用 `QT_SCALE_FACTOR` 离屏复现法验收。0.4.x 到此为止，不再加码。

### 0.5.x：Agent 闭环与真实验证

主题不是运行时整合——`App` 生命周期、配置、单实例、托盘、退出收尾已经完成。本段做三件事：

- **组件索引**：`psi6.ui` 控件的机器可读清单（名称、构造参数、适用场景），Agent 不读源码就能选对控件。
- **规范检查器**：AST 级检查 SKILL.md 的禁令（业务代码 `QFileDialog`、手写 `QThread`、散落 QSS），并入模板 `--check`。模板从「能跑」升级为「写得对」。
- **小块补全**：日志落地、配置版本迁移。

门禁：一个真实应用用已发布的 psi6 构建并发布；CI 在 Windows / Ubuntu / macOS 三平台真实跑绿。

### 0.6.x：生产能力

按真实应用的反馈补任务观测、结果管理、应用诊断、发布前检查。任务依赖和持久化队列只有需求明确时才加入。打包仍交给 `pyside6-deploy`，psi6 只做应用侧的集成与诊断。

### 1.0：稳定平台

核心 API 冻结，迁移策略明确，跨平台边界写清，持续支持多个不同类型的真实桌面应用。

## 门禁说明

版本号是阶段划分，不是时间表。任何一段的验收条件没达到，就继续做，不提前宣布完成。跨平台验证和真实应用验证不是可选项：CI 不绿不发次版本，真实应用没跑过不进 1.0。
