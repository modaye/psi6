# 0003：Modern Desktop Workbench

## 方向

psi6 的下一阶段是一套可组合的桌面界面，不是再增加配色主题。旗舰方向叫 Modern Desktop Workbench：桌面习惯参考 Fluent，数据密度参考 Carbon，视觉原则是现代简约。

辨识度来自比例、图标、排版和状态。不把 Material 外观、工业监控或 Web 仪表盘当作默认主题。浅色和深色是同一套语言的两种底。`style` 只决定 `modern` 或 `compact` 密度。

具体色值待文件批处理、数据检查和高密度工作台三个原型的真实窗口审定后再冻结。用色先按角色，不按另一套皮肤：悬停用中性灰，持久选中用强调色浅底，实心强调色只给主按钮、焦点和当前项的边框。菜单上的高亮仍是悬停。

## 原则

- 内容优先。层次靠表面和边框，表格和表单可以共用画布。
- 精致但不浮夸。玻璃、渐变和动画只留给浮层。
- 适合长时间工作。密度用 `style`，不靠加大圆角。
- 复杂工作一起做：排序、筛选、分栏、进度、取消和错误详情。
- 这一阶段先保证焦点、键盘和窗口行为。右键菜单已落地（`psi6.ui.context_menu`）。结果表行拖放要显式打开，下面列出的组件随后做，不从产品里划掉。

## 职责

- 运行时、任务、配置继续做基础设施，不作为这一阶段的主要展示。
- `AppShell` 负责侧栏换页。`Workspace` 负责一页里的工具栏、面包屑和左右栏；栏可显隐，拖动后的宽度按栏名记录，`state()` / `save_state()` 导出并持久化到 `ConfigStore`。
- `TabView` 负责这一页里的多份文档：可关闭、可拖动重排、全关掉显示空态；状态只记 `keys` 顺序与 `current`，不记控件，恢复时先用 `add_tab` 放回控件再对齐顺序。
- `DataTable` 目前是结果表，加上排序。行按需增量渲染（`fetchMore`），不预先为几万行建 Item；树表、分页和列管理如果要做，单独成控件，不塞进这张结果表。列管理已按这条边界落地：`ColumnPicker` 负责面板与状态，`DataTable` 只给 `columns()` / `visible_columns()` / `set_visible_columns()` / `column_menu()` 四个读写口。
- `pydantic_form` 继续由模型生成字段。分组和可搜索选项是字段 metadata。控件范围不等于模型校验。

## 剩余

壳、排序、分组表单和三个原型的第一版已经落地。这一方向继续做审定，不转回去做组件索引、规范检查器或新的控件种类。

现在：三个原型的主区宽于侧栏，表头用可读标题。工作区留白跟着主题的间距走，切到紧凑密度时壳也会收紧。密度页不另切一套皮肤。检查页打开时能看到长说明和对应属性，表单页打开时能看到字段错误。

审定前先不冻结色值、阴影和默认主色，也先不加一整套新皮肤，避免窗口还没看过又换一套颜色。

随后做，不挡这次审定：树表、命令面板、Markdown、图表、任务队列。已落地的四项：`DataTable` 的虚拟滚动（原始行索引 + `fetchMore` 分批发布），多视图文档与可持久化面板布局（`TabView` + `Workspace.state()` / `ConfigStore`），统一右键上下文菜单（`psi6.ui.context_menu`：`MenuAction` 描述项，`MenuTarget` 给出命中的行 / 节点 / 页签，`DataTable` / `TreeView` / `TabView` 各自挂载），以及列管理（`ColumnPicker` 独立控件 + 列头右键 `column_toggle_menu`）。拖放排序在 `TabView` 内已可用（标签拖动重排）。结果表行拖放要显式 `DataTable.set_reorderable(True)`，排序或筛选进行中时不改顺序。配色主题可以在现有色板冻结之后再加。Widgets 达不到目标时再评估 QML。

真实窗口看过之后，把通过的比例和表面层级写进这份规范。全量组件索引、日志落地、配置迁移仍等真实应用提出。三系统 CI 和真实应用发布是 1.0 的门禁，不挡这次界面。

## 不做

不引入 QFluentWidgets。不把 PDF、CAD 或浏览器自动化放进核心。QML 只在 Widgets 达不到目标时再评估。面板布局用固定左中右栏的显隐与宽度持久化实现，**不引入 `QDockWidget` 浮动窗口或自由停靠**：那会带来状态矩阵和序列化复杂度，而这一阶段要的只是「关掉的栏下次还是关着」。
