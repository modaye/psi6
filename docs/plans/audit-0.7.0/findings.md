# 0.7.0 阶段一：改前视觉审计

状态：阶段一门禁已完成。这里只记录真实窗口里看得见的问题。色值还没冻结，控件外观还没改。

截图在 [`before/`](before/)。清单是 [`before/manifest.json`](before/manifest.json) 和 [`before/manifest-dpi.json`](before/manifest-dpi.json)。重新截图：

```powershell
uv run python scripts/visual_audit_070.py
```

## 环境

| 项 | 值 |
| --- | --- |
| 系统 | Windows 11（10.0.26200），可用区域 2560×1392 |
| 系统缩放 | 100%（`devicePixelRatio` 1.0，逻辑 DPI 96） |
| Python | 3.13.9 |
| 窗口 | `App.run` 打开的真实窗口，不是离屏平台 |
| 150% | 单独进程设置 `QT_SCALE_FACTOR=1.5`。这是逻辑缩放，不是 Windows 显示缩放 150% |

系统显示缩放 125%、150%、175%、200%，以及 macOS、Linux，这次没有跑。不能写成已验证。

抓图方式：

- 原生标题栏窗口（看板、设置、文件索引、任务、对话）用屏幕上的 `QScreen.grabWindow`。
- 组件目录和画廊是自绘标题栏，开了透明背景。`grabWindow` 得到整张黑图，已作废。这两类改用已经显示出来的窗口的 `widget.grab()`，清单里 `source` 为 `widget`。

四种组合都截了：`light`、`modern-dark`、`compact`、`compact-dark`。组件目录按 kit 的实际默认打开焦点环。画廊和场景按画廊的实际默认关闭焦点环。

700×520 的窄窗口截图是审计脚本把最小尺寸放开之后才得到的。不放开时，窗口停在约 921–977×785，浅色现代的控件高度仍是 36，没有触发「宽度小于 760 就收紧」的规则。

## 现在已经站得住的部分

这些不要在下一阶段推倒：

- 浅色画布是白的。深色看板、设置和组件目录的窗口、侧栏、卡片能分开，不是纯黑叠在一起。
- 主按钮和危险按钮一眼能认出来。成功、警告、失败、信息这组标签是目前最清楚的语义色。
- 日志级别用了颜色，错误行是红的。
- 表单错误有文字，不只有颜色。空状态有图标、标题和一句说明。
- 收紧后度量会变：宽窗口现代是控件高 36、圆角 6；700 宽触发之后是控件高 30、圆角 4。
- 150% 逻辑缩放下，看板、设置和文件索引的整体结构没有散掉。

## 问题

每条都对应截图。功能还没做的控件（日期选择、树表、属性检查器等）不记在这里，它们仍在 0.8.0。

### V-01 页面是一小块控件加一大片空白

组件目录的按钮、输入、选择、反馈、表单，内容都挤在上方，下面大半窗是空的。设置页的字段拉满整行，组与组之间空得很大。对话页消息和输入条之间是一整块空白。任务页的客户区里只有「开始」和「取消」，两个按钮浮在正中。

证据：

- `before/kit/light/buttons.png`
- `before/kit/light/inputs.png`
- `before/kit/light/choice.png`
- `before/kit/light/formlab.png`
- `before/scenes/light/settings.png`
- `before/scenes/light/chat.png`
- `before/scenes/light/task.png`

深色同一批页面结构相同，见 `before/kit/modern-dark/` 和 `before/scenes/modern-dark/`。

这是组合问题，不是缺一个按钮样式。阶段二的参考页必须先规定内容区怎么占满窗口：工具栏、表单行宽、空状态属于哪一块，而不是让控件贴顶、其余留白。

### V-02 键盘焦点默认看不见，打开之后主按钮上的环也很弱

`App` 默认 `focus_ring=False`。画廊和场景都是这个默认值。

组件目录显式打开了焦点环。把同一张按钮页在聚焦前后做像素对比，`kit/light/buttons.png` 和 `kit/light/buttons-focus.png` 只有 348 个像素不同，范围落在「开始」按钮上（约 232,107–281,142）。环是有的，但是主按钮边缘上的一圈浅线，整页里几乎认不出当前焦点。

证据：

- `before/kit/light/buttons-focus.png`
- `before/focus-off/light/buttons-focus.png`
- `before/kit/light/states.png` 的「焦点」行
- `before/kit/modern-dark/states.png` 的「焦点」行

状态矩阵里，输入框的焦点是整圈粗蓝框，和按钮上的浅环不是同一种焦点。阶段二要定一种环：主按钮、次按钮、输入框都能看见，并且不改变控件外框尺寸。

### V-03 状态矩阵列被拉散，而且覆盖的控件不够

状态页只有主按钮、次按钮、输入、侧栏四列。输入列把表格拉满，侧栏列贴到窗口右缘，和前面三列断开。次按钮的悬停和默认都接近白底灰框。主按钮的悬停和按下能分开，禁用仍像一颗褪色的主按钮。

错误行做对了一半：输入有红框，旁边有红字。按钮列写着「不适用」。没有危险按钮、表格、树、页签、横幅、Toast。

证据：`before/kit/light/states.png`、`before/kit/modern-dark/states.png`、`before/kit/compact/states.png`、`before/kit/compact-dark/states.png`。

数据页自己的表格状态是另一套：选中行有浅蓝底，「就绪 / 等待 / 失败」只是灰色字，和上面那排彩色标签不是一种语言。见 `before/kit/light/data.png`。

### V-04 窄窗口会裁字，而且正常拖动到不了收紧阈值

700×520 时，侧栏里的「psi6」被挤乱，多视图左栏的「打开后可拖动标签重排」后半被切掉，工具栏五个按钮顶在一起。数据页在 1180×785 和 700×520 下内容高度都超过视口，页面没有滚动，底部有被挡住的风险（清单里 `clipped: true` 的是各主题的 `data`，以及窄窗口下的部分表单和多视图）。

证据：

- `before/kit-narrow/light/workbench.png`
- `before/kit-narrow/light/data.png`
- `before/kit-narrow/light/formlab.png`

同一套裁切在深色和紧凑主题的窄图里也有，目录是 `before/kit-narrow/`。

不放开最小尺寸时，组件目录停在 900 像素以上，文档里的 760 阈值不会发生。阶段二要同时处理两件事：窗口应当能收到该收的宽度；收到之后文字、侧栏和工具栏不能被切掉，放不下的内容要能滚动。

### V-05 次要控件的边界太轻，按钮文字被省略号吃掉

「取消」「浏览」「校验」接近白底或浅灰底，和禁用差不多。「浏览...」「导出日志...」在 100% 和 150% 都是省略号。文件索引里，「全部」下拉压在左右栏分界上；「开始」在左上，「取消」在右上，两个动作不在一组。

证据：

- `before/scenes/light/file-index.png`
- `before/dpi150/scenes/light/file-index.png`
- `before/scenes/compact/file-index.png`
- `before/kit/light/formlab.png` 底部整行的「校验」

### V-06 同一种错误有两种样子

状态矩阵里的错误输入是红框加红字。表单页的数量错误只有字段下面一行红字「数值过小」，输入框本身仍是灰底。深色状态矩阵里，这行红字偏粉，贴在深底上，比浅色更难读。

证据：`before/kit/light/states.png`、`before/kit/light/formlab.png`、`before/kit/modern-dark/states.png`、`before/scenes/modern-dark/settings.png`（未选中的复选框框线也很弱）。

### V-07 空状态和反馈没有落在自己的区域里

数据页上方有一张有数据的表，中间放了一个「暂无数据」，下面又是一张有数据的表。反馈页的日志已经有五行，下面再放一个「暂无数据」。空状态看起来像整页没内容。

横幅本身能看清警告。它右边的关闭按钮是一颗实心蓝块，比警告横幅更抢。

证据：`before/kit/light/data.png`、`before/kit/light/feedback.png`。文件索引把空状态放进了结果区，这个关系是对的，见 `before/scenes/light/file-index.png`。空状态控件可用，放错位置的是目录页的组合。

### V-08 多视图的三栏不是同一种表面

宽窗口下，中间是一块有边的文档区，左边的「文档列表」和右边的「属性」直接写在画布上。页签和面包屑能读。窄窗口下这三栏开始互相挤、文字被切，见 V-04。

证据：`before/kit/light/workbench.png`、`before/kit-narrow/light/workbench.png`。

### V-09 侧栏图标没有分开，底部多出一个空项

导航项大多是同一种文档图标，选中项只靠浅蓝底。列表底部还有一个没有文字的空图标。四种主题都在。

证据：`before/kit/light/buttons.png` 以及任意一张组件目录图的左栏。

### V-10 画廊和工具页不是一套版式

画廊首页是卡片网格，分组、图标、摘要都齐，是这次截图里最完整的一屏。它的主题切换只有「浅色 / 深色 / 紧凑」，没有「深色紧凑」。工具页则是 V-01 那种空白画布。

证据：`before/gallery/light/home.png`、`before/gallery/compact-dark/home.png`。

阶段二不要把画廊的卡片墙当成应用页的默认结构。卡片适合做入口，不适合做文件索引和设置。

## 这次没有当成缺陷的事

- 最小窗口客户区是空白，因为示例只设了标题。系统标题栏不在客户区抓图里。见 `before/scenes/light/minimal.png`。
- 悬停和按下来自状态页的模拟属性，不是这次用鼠标逐个点出来的。真实指针下的悬停仍要在阶段四再看。
- 150% 没有出现新的整页错位。已有的省略号和分栏挤压在 100% 就存在。
- 机器可读目录里还没有的控件，不记成视觉缺陷。

## 阶段二要先决定的事

审计之后才能写规范。下一份文档要回答这些，而不是先改 QSS：

1. 工作台页、设置页、任务页各自的内容区怎么占满窗口，行宽上限是多少，空状态属于哪一块。
2. 焦点环用哪一个 token，在主按钮、次按钮、输入框上分别长什么样，外框尺寸如何保持不变。默认改为可见。
3. 错误态只保留一种：框和文字一起变，深色下字色对比够。
4. 状态矩阵按控件族重排，列不再被拉散；表格、页签、横幅补进矩阵。
5. 窄于 760 时侧栏、工具栏和长标签怎么收，页面超出视口时怎么滚动。
6. 旗舰浅色和深色哪些角色维持现在的值，哪些因为对比不够要改。这次不在审计里提前写新色值。
