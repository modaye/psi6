# psi6 0.7.0 需求计划：Visual Foundation

状态：阶段二规范已起草，审定通过之前，不按本文改主题、控件或 QSS。规范在 [docs/design/0.7.0](../design/0.7.0/README.md)。

版本目标：让已经存在的控件，在同一套桌面设计语言下变得一致、好看、可键盘操作，并且能在真实窗口里验收。0.7.0 交付的是视觉基础，不是新的控件清单。

判断标准沿用外部评审的那一句：psi6 的取舍，看编码 Agent 能否在较短时间内生成一款漂亮、专业、可靠的 Windows 桌面软件。0.7.0 先保证「已有零件拼出来的窗口」达到这个标准。控件覆盖面放到 0.8.0，Agent 设计闭环放到 0.9.0。

本文同时区分两件事，后续需求不得混写：

- **框架的开发者体验**：Agent 和人类作者如何选控件、写主题、通过检查。
- **生成应用的最终用户体验**：窗口、密度、焦点、反馈、空状态在屏幕上是否像一款现代桌面软件。

0.7.0 的主交付物是后者的视觉质量，以及前者里直接服务这件事的规范、工作台和验收。运行时、任务、托盘、配置的行为保持 0.6.0 的契约。

## 1. 为什么是这一版，而不是继续加功能

0.6.0 已经具备统一入口（`App`、`TaskRunner`、`Theme`、`DesktopWindow`）、`Workspace` / `TabView`、`DataTable` 增量渲染与列管理、`TreeView`、上下文菜单、快捷键、撤销、Toast、`FloatBall`、组件目录和 `python -m psi6 check`。这些能力保留。

对照代码，评审指出的深层缺口是事实：

- 色板在 README 和 [ADR 0003](../adr/0003-workbench.md) 里写明尚未冻结。`Tokens` 仍是扁平颜色加尺寸，阴影、语义间距阶梯、字号阶梯都没有独立角色。
- `src/psi6/theme/apply.py` 里圆角大量写成 `radius`、`radius + 4` 或写死的 `9px` / `7px` / `4px` / `2px`。控件并没有共享一套圆角层级。
- 间距只有 `space_sm` / `space_md` / `space_lg`（modern 为 8 / 12 / 16）。4px 基准没有变成可引用的语义间距。
- 字体栈已经优先 `Segoe UI Variable Text`，字号只有 18 / 13 / 12 三档（compact 为 16 / 12 / 11）。
- `App(..., focus_ring=False)` 是默认值。聚焦时全局样式只写 `outline: none`，键盘用户看不到焦点。纯函数 `build_stylesheet` 的默认却仍是打开。Skill、模板和 README 都在教 Agent 默认关掉。
- 视觉回归 `tests/test_visual_regression.py` 只断言按钮填充色接近 token，不看页面、裁切、留白和焦点。
- `python -m psi6 kit` 与 `python -m psi6 gallery` 分成两个入口。kit 有状态矩阵，gallery 有三张组合场景，两者都还不是设计系统工作台。
- `set_style` 同时接受字面色和 token 名。Agent 可以在统一主题旁边写下互不相关的颜色。

0.4.0 已经定过、并且实现已经遵守的轴，本版保持不变：

| 轴 | 含义 | 取值 |
| --- | --- | --- |
| `Theme.base` | 配色 | `light` / `dark` / `auto` |
| `Theme.style` | 尺寸与密度预设 | `modern` / `compact` |
| `App.density` | 运行时是否随窗口改尺寸 | `auto` / `modern` / `compact` |

`base = "auto"` 已经实现，并有测试。0.4 草案里「base 只写 light 或 dark」是过时表述。0.7.0 要统一文档，不回退实现。`App.density` 不是第三个主题轴：它只在运行时把 compact 或 modern 的尺寸预设压到当前主题上，不改配色。文档必须把这三件事写成三句话，避免 Agent 再发明 `Theme.density`。

额外皮肤 `Mono`、`Obsidian`、`Pine`、`Brass`、`ModernDark`、`CompactDark` 继续能加载、能过对比度检查。0.7.0 不新增皮肤，也不把它们重做成旗舰。旗舰只有四种组合：Light/Dark × Modern/Compact，而且四种组合共用一套语言。

下列原则继续有效，需求不得违反：

- 默认多开。`single_instance=True` 才加锁。
- `DesktopWindow` 默认原生标题栏。`frameless=True` 才自绘。
- 关窗口、点取消、应用退出是三件事。
- 主题用 Python 类，字段名必须是 `Tokens` 字段。不引入 JSON / TOML / YAML 主题文件。
- 业务模板和行业界面不进入框架核心。
- 不引入 `QDockWidget` 自由停靠，不引入 QFluentWidgets，不引入 QML。
- `FloatBall` 保持可选。设计工作台的主路径不把它当成窗口的一部分。

## 3. 硬性约束

执行 0.7.0 的人或 Agent 遵守下面十条。违反任何一条，该阶段不算完成。

1. 视觉升级必须来自 token、状态规则和布局。只改几个颜色值并让旧测试变绿，不算完成。
2. 单元测试通过不算视觉完成。验收材料里要有真实窗口截图。
3. 设计工作台展示的是控件状态和真实页面结构。禁止用一堆无意义圆角卡片凑一屏。
4. 阶段二的规范合入之前，不修改控件外观实现。允许的代码改动只有审计脚本、截图夹具和文档草案。
5. 每个纳入范围的控件都有状态矩阵，并且在工作台里能看到。
6. 验收同时覆盖单个控件和至少三张组合页。
7. 截图来自真实显示的窗口。离屏 `QWidget.grab` 可以辅助对比度取样，不能单独作为「好看」的证据。Qt 的离屏平台不画原生焦点框，焦点必须在真实窗口里看。
8. `psi6.api.STABLE` 的职责保持不变。控件公开构造参数保持兼容。必须破坏行为时（焦点环默认值）单独写迁移说明。
9. 键盘焦点必须看得见。不允许再用默认关闭焦点环换取画面干净。
10. 没有阶段四的验收记录，不把版本号改成 0.7.0，也不在 CHANGELOG 里写成已完成。

## 4. 现状基线

阶段一对照这份基线审计，避免把已有能力再做成新控件。

### 4.1 已有 token

`Tokens` 是带默认值的冻结数据类。主题子类的类属性必须命中字段名，未知字段在加载时抛错。新增字段只要有默认值，旧主题类仍然合法。

已有颜色角色：窗口 `color_bg`，面板 `color_surface`，浮层 `color_elevated`，凹陷 `color_sunken`，悬停 `color_hover`，按下 `color_pressed`，选中 `color_selected`，正文 `color_text`，辅助 `color_muted`，结构边 `color_border`，弱分隔 `color_border_subtle`，控件边 `color_control_border`（空则等于结构边），禁用 `color_disabled`，主色及其上的字色、悬停、按下，危险色及其悬停按下，成功、警告、信息，焦点 `color_focus`，遮罩、侧栏、用户气泡。

已有尺寸：`space_sm/md/lg`，单一 `radius` 与 `button_radius`、`window_radius`，控件高度 36/28（compact 30/24），行高 32（compact 28），图标 16（compact 14），焦点环宽 2。

已有字体：`font_family` 以 Segoe UI Variable Text 为首，中文回退 Microsoft YaHei UI；等宽是 Cascadia Mono / Consolas。字重只有正文 400 和标题 600。

已有动效：`motion_fast_ms` 160、`motion_ms` 220，`reduced_motion` 置 1 时两者变为 0。

没有的角色：阴影、多级圆角语义名、4px 间距阶梯的命名、说明文字 / 标题以上的字号、表面「卡片」和「选中表面」的独立名字。这些缺的角色由阶段二决定是新字段，还是映射到已有字段。已有字段名保持不变。0.4 草案里的 `window_bg`、`text_primary`、`accent` 只作为规范里的别名说明，不作为 Python 字段名。

### 4.2 已有公开控件

`psi6.ui.__all__` 已经覆盖评审清单里的大部分基础件和若干复合件，包括按钮四态工厂、`IconButton`、`SearchField`、`FileInput` / `FolderInput`、`Switch`、`SegmentedControl`、`DataTable`、`TreeView`、`LogConsole`、`LogPanel`、`ColumnPicker`、`EmptyState`、`Banner`、`StatCard`、`Stepper`、`Toast`、`AppShell`、`Workspace`、`ToolBar`、`Breadcrumb`、`TabView`、`CommandPalette`、`ShortcutBook`、`SettingsPage`、`FormView`、`ContentDialog`、上下文菜单、`StatusProgress`。

阶段三改的是这些控件的外观和状态，不是一份新的控件目录。评审清单中「建议完善的能力」若对应的控件已经存在，0.7.0 只做视觉和状态；能力缺口记入 0.8.0 附录，不在本版开新模块。

### 4.3 已知的规范冲突

| 话题 | 实现 | 文档里容易打架的说法 | 0.7.0 的统一口径 |
| --- | --- | --- | --- |
| `base` | `light` / `dark` / `auto` | 0.4 草案写 base 只决定浅色或深色 | 三者都合法。`auto` 跟随系统，变体自己的 `base` 不能再是 `auto` |
| `style` | `modern` / `compact`，只影响尺寸 | 曾和 `density` 混写 | 主题上只有 `style` |
| `App.density` | `auto` 默认，空间不足或高 DPI 启发式时收紧，不放宽 | Skill 里的 `density="auto"` 容易被读成主题字段 | 这是 `App` 的运行时策略，不是 `Theme` 的属性 |
| 焦点环 | `App` 默认关；样式函数默认开 | Skill 要求需要时再打开 | 改为 `App` 默认开，和样式函数一致 |
| 色板 | 浅色主色 `#2b5cd7`，深色主色 `#6e9ff2`，且另有六套皮肤 | ADR 0003 写明审定前不冻结 | 四种旗舰组合审定后冻结；其余皮肤只保证不坏 |

## 5. 需求

每条需求都有验收。验收不满足，该条不算完成。色值、精确间距和圆角数字不在本节锁死，它们是阶段二的产出，阶段四冻结。

### VF-01 视觉语言

建立一份默认设计语言，四种组合共用。方向维持 ADR 0003：桌面习惯参考 Fluent，数据密度参考 Carbon，视觉原则是克制的现代工作台。辨识度来自比例、表面、边框、排版和图标，不来自另一套皮肤。

规范必须写清这些决定：

- 表面至少区分窗口背景、内容表面、凹陷输入、卡片或分组、浮层（菜单、对话框、Toast）、选中表面。层次靠表面差和边框，阴影只给浮层。
- 应用根部不是一整屏圆角卡片。表格、工具栏、分隔线和紧凑信息区可以贴着内容表面，用分隔线分区。
- 结构边框（分区、卡片、对话框）与控件边框（输入、普通按钮、勾选）继续分成 `color_border` 与 `color_control_border` 两个角色。
- 实心强调色用于主按钮、当前项标记和焦点。悬停保持中性。持久选中用强调色浅底。这条已在 0.6.0 的交互里成立，规范要把它写成不许推翻的规则。
- 图标使用同一线宽和同一光学尺寸，颜色跟语义 token，不跟写死的十六进制。
- 动效只用 `motion_fast_ms` 与 `motion_ms`。`reduced_motion` 打开时，相关动画直接到位。
- 字体继续 Windows 优先 Segoe UI Variable，并写明 macOS、Linux 的回退族。回退族的真实渲染放到 1.0 的平台验收，本版只要求 token 和文档一致，不假装已经在那两个系统上看过。

验收：

- 文档给出四种组合的同一页对照说明，指出哪些 token 随 `base` 变、哪些随 `style` 变。
- 工作台能在不重启进程的情况下切这四种组合。
- 任一参考页里，不存在「为了现代感而套上的无信息卡片」。

### VF-02 设计 token

在不重命名现有字段的前提下，补齐规范所需要的角色。

阶段二先做一张映射表：规范角色 → 现有字段或新字段。只有映射表里确实没有落点的角色才新增字段，并且必须有默认值，使旧的 `Theme` 子类无需修改即可加载。

本版预期要补、但以阶段二定稿为准的方向：

- 间距：以 4px 为步长的语义间距，覆盖现有 `space_sm/md/lg` 表达不了的紧间距和区块间距。布局代码引用 token，不再写散落的像素。
- 圆角：窗口、控件、菜单项、勾选指示器使用刻度上的值。`apply.py` 里的魔术圆角改为引用这些值。
- 字号：在标题、正文、辅助之外，补规范需要的级别（例如区块标题、说明文字）。compact 有自己的一档，不另做一套字体家族。
- 阴影：仅浮层使用。卡片默认无阴影。
- 状态色：继续「留空则推导，写值则覆盖」。推导规则写进规范，主题作者不自己 `mix` 颜色。

验收：

- 未知字段仍然加载即抛错。
- 只设置 `color_primary` 的自定义主题，悬停、按下、选中、焦点仍能推导，并且对比度诊断没有新增的正文级失败。
- `python -m psi6 theme <名称> --check` 覆盖新增的语义配对。
- modern 与 compact 的数值差只出现在尺寸预设里。配色不因为 `style` 而改变。

### VF-03 冻结默认色板

阶段二用真实窗口审定默认浅色和默认深色。通过之后，把核心语义色写进规范，并在 CHANGELOG 里声明：这些角色在 0.7.x 内不再因审美偏好反复改值。

冻结范围是旗舰四种组合所用的默认 `Tokens.light()`、`Tokens.dark()` 以及 modern / compact 尺寸预设。`Obsidian` 等皮肤的色值不在冻结范围里，它们继续是可选主题。

浅色背景维持纯白 `color_bg`。深色避免纯黑叠纯黑：窗口、表面、浮层必须能在截图里分开。

验收：

- 冻结表列出每个核心角色的色值、用途、以及它和相邻表面的对比关系。
- `contrast_notes` 对冻结后的浅色和深色没有正文级失败。焦点环对所在表面至少达到 3:1。主按钮上的焦点环继续使用 `color_on_primary` 这一已经验证过的做法，因为焦点色和主色同色相时对比不够。
- README 去掉「色板尚未冻结」中已经冻结的那一部分，并写明仍未冻结的剩余项（若有）。

### VF-04 键盘焦点默认可见

`App` 的默认改为绘制焦点环，与 `build_stylesheet`、`psi6_button_stylesheet`、`apply_theme` 的默认一致。`focus_ring=False` 仍然可用，供明确不需要键盘焦点外观的场景。

焦点环的绘制规则：

- 使用统一的环，而不是每个控件各画一种。
- 聚焦不改变控件外框尺寸，不推动相邻布局。0.6.0 已经用 padding 与 min-height 补偿过，这条补偿保持，并用真实窗口确认。
- 链接一类文字控件可以用下划线表达焦点，不必套方框。
- 填充按钮上的环使用在该填充色上可见的颜色。
- 禁用控件不画环。
- 鼠标点击产生的焦点也显示环。桌面软件不隐藏鼠标用户的焦点；环的样式要精致，而不是关掉。

这是本版唯一计划中的默认行为变化。迁移说明写进 `MIGRATION.md`：要恢复 0.6.0 外观的应用传 `focus_ring=False`。Skill 和模板改为默认可见，并说明如何关闭。

验收：

- 新的 `App` 不传 `focus_ring` 时，`app.focus_ring is True`，全局样式和主题按钮都含焦点规则。
- Tab 键在参考页上移动时，真实窗口截图能指出当前控件。
- 开启和关闭焦点环时，同一按钮的外框宽高一致。
- 现有 `tests/test_focus_ring.py` 更新为新的默认，并保留「显式关闭则不画环」的用例。

### VF-05 已有控件的状态矩阵

状态矩阵是验收标准。每个纳入控件在工作台中能看到它适用的状态，浅色和深色都要有，modern 和 compact 至少各有一张完整抽样。

最低矩阵：

| 控件族 | 必须能看出的状态 |
| --- | --- |
| 主按钮、次按钮、危险按钮、文字按钮、图标按钮 | 默认、悬停、按下、焦点、禁用；主按钮和危险按钮另加加载中（若该按钮已经有加载表现，没有则本版不加新 API） |
| 输入框、搜索框、路径输入 | 默认、悬停、焦点、错误、禁用、只读；有清除或前后缀时这两种装饰在焦点和错误下仍对齐 |
| 勾选、单选、开关 | 未选、已选、半选（仅勾选）、禁用、焦点 |
| 分段控件 | 默认、悬停、选中、焦点、禁用 |
| 页签 | 默认、悬停、选中、关闭按钮悬停与按下、禁用（若支持） |
| 表格 | 默认、行悬停、行选中、表头排序、空、忙 |
| 树 | 展开、折叠、悬停、选中、空、忙 |
| 对话框 | 普通确认、危险确认 |
| Toast | 信息、成功、警告、错误；开启动效时能进入和离开，`reduced_motion` 时直接出现 |
| 横幅、空状态 | 四种语义里横幅已经支持的那些；空状态含说明和动作 |
| 导航项 | 默认、悬停、当前项、焦点、禁用 |

高 DPI 抽样见 VF-09，不要求每种状态都在每个缩放下人工截一张，但每种控件族至少在 100% 和 150% 各有一张真实窗口图。

验收：

- 工作台有一页（或按控件族分页）覆盖上表，缺一格就要有书面理由（该控件没有这个状态）。
- 禁用态同时失去交互和变得可辨认，不只靠整体透明。
- 错误态除颜色外还有文字。规范禁止只靠红框表达校验失败。

### VF-06 `set_style` 的边界

`set_style` / `Style` 保留。它继续只服务单个控件的字号、字重、颜色、填充、圆角和内边距，颜色可以是 token 名，换主题后 token 名重算。

本版增加的约束：

- 文档和 Skill 写明推荐顺序：优先用控件变体和语义 token；`set_style` 是例外，不是给每一行字上色的办法。
- `python -m psi6 check` 能发现应用代码里 `set_style`、`Style`、`Icon.set_color` 使用的字面色（`#RGB`、`#RRGGBB`、`rgb`、`rgba`）。token 名不算问题。
- 这条诊断的编号、严重级别和退出码在实现时定稿，并写进检查器帮助。默认不要把已经发布的应用在未改代码的情况下打成失败；提供明确的严格开关，模板和新的 Skill 示例走严格路径。字面色诊断的存在本身是本版验收项。
- 主题切换后，token 名仍然重算，字面色保持调用时的值。这一现有行为保持，并补测试。

验收：

- 使用 token 名的 `set_style` 在 `set_theme` 之后颜色跟着新主题。
- 使用字面色的调用能被检查器报告，位置落到文件和行。
- 框架自己的控件实现不通过 `set_style` 写字面色。控件外观只读 token。

### VF-07 文档、Skill 与检查口径

下列位置对 VF-03 的冻结结果、VF-04 的默认值、以及第 4.3 节的三轴口径使用同一套句子：

- `README.md`
- `MIGRATION.md`（仅焦点环默认值这一条行为变化）
- `CHANGELOG.md`（实现完成之后才写 0.7.0 节）
- `skills/psi6-desktop/SKILL.md`
- `skills/psi6-desktop/template/app.py`
- `python -m psi6 theme` 的帮助文本
- `docs/adr/0003-workbench.md` 里「色板尚未冻结」的句子，在冻结完成后改成指向本计划和冻结表

Skill 在 0.7.0 增加的是短规则：四种组合怎么选、焦点默认可见、页面不要做成整屏卡片、颜色用 token、`set_style` 是例外、布局用 `Workspace`。长篇设计文放在 `docs/`，Skill 链接过去。不在本版把 Skill 拆成评审所画的整棵 `design/` `patterns/` `templates/` 目录，那是 0.9.0 的结构。

验收：

- 仓库内检索不到互相矛盾的 `focus_ring` 默认说明。
- 检索不到把 `App.density` 写成 `Theme` 字段的现行文档。历史 ADR 可以保留原文，但要加一句「以 0.7.0 计划为准」。
- 模板 `python app.py --check` 仍然通过。

### VF-08 设计工作台

`python -m psi6 kit` 成为设计工作台的入口。`python -m psi6 gallery` 保留为打开同一工作台或明确转发，避免两个程序展示两套外观。

工作台至少包含：

- 当前 token 的只读对照：颜色、字号、间距、圆角、阴影。本版不做可视化 token 编辑器，也不从工作台导出主题类。
- Light / Dark 与 Modern / Compact 的切换，切换后已打开的页面一起更新。
- 全部纳入 VF-05 的控件状态。
- 三张参考页：数据管理、设置、任务工作区。用已有的 `Workspace`、`DataTable`、`SettingsPage`、`LogPanel` 或 `LogConsole`、`StatusProgress`、`EmptyState` 组合。参考页的数据是固定示例，不接真实业务。
- 窗口宽度至少能在舒适宽度和窄宽度（触发 `density="auto"` 收紧的宽度附近）各看一次。
- 每个状态页能复制一段使用该控件的 Python 片段。片段使用公开 API。

工作台自己调用 `focus_ring` 的默认（打开）。主题页不再把「关闭焦点环」当成推荐路径；可以保留一个开关，用来对照 VF-04 的关闭行为。

验收：

- 一条命令打开工作台，不需要再记 kit 和 gallery 哪个才是标准。
- 三张参考页在四种组合下都有截图。
- 工作台源码通过 `python -m psi6 check`。

### VF-09 真实窗口视觉验收

在 Windows 上，用真实显示的窗口验收。本机做得到的缩放都要看：100%、125%、150%，以及系统允许时的 175% 或 200%。做不到的缩放写明原因，不记为通过。

每种缩放下至少看：工作台首页、一张含表格的参考页、一张含表单的参考页、焦点落在主按钮和输入框上的画面。检查项：

- 控件没有画出窗口或所在面板。
- 文字没有被裁切，中文和英文都能完整显示。
- 没有无解释的大块空白，也没有控件贴死在一起。
- 四种组合都能切换，切换后没有停在上一套颜色的按钮或图标。
- 图标在该 DPI 下边缘清楚。
- 焦点环可见，且聚焦前后外框不跳动。

自动化部分：

- 保留现有颜色不变量测试，继续防止主题按钮停在旧主色。
- 增加一套可重复的截图夹具：固定窗口逻辑尺寸、固定示例数据、固定主题组合，把截图存入验收目录。夹具说明写明显示平台、DPI 和 PySide6 版本。
- 不把跨机器像素级比对设为 CI 失败条件。CI 继续跑不变量。像素比对只在同一台验收机器上作为人工对照。

macOS 与 Linux 不作为 0.7.0 的退出条件。验收记录里列一张「未在本版验证」的表，内容包括这两个系统、多显示器切换、原生文件对话框在高 DPI 下的位置。这张表原样留给 1.0.0。

验收：

- 仓库里有阶段一的改前截图、阶段四的改后截图，以及一张问题对照表。
- 对照表里每一条审计问题标为已解决或延期，延期项写明放到哪一版。
- 未解决问题为 0，才允许发布 0.7.0。延期必须是第 2.2 节已有的后续范围，不能把 VF-01 到 VF-09 的失败改名叫延期。

### VF-10 参考页所证明的组合质量

三张参考页各自证明一件事，不承担新功能。

- **数据管理**：工具栏、筛选或分段、结果表、空状态、侧栏或详情的宽度关系。表头与单元格对齐，选中行看得出，窄窗口时工具栏不把按钮挤出窗口。
- **设置**：分组标题、字段、说明、校验错误的纵向节奏。标签和控件对齐。有一行能看出「已修改」或保存结果的现有反馈；不新增保存状态机。
- **任务工作区**：配置区、开始与取消是分开的按钮、状态栏进度、日志。取消仍只是请求。这张页用来确认任务界面不再是「一根进度条加一段字」的唯一形态，同时不新增任务中心。

验收：三张页都由公开控件组成，源码可作为 Agent 的组合范例被 Skill 点名。页内不出现手写 `QFileDialog`、手写 `QThread` 或内联 QSS。

### VF-11 图标与动效的最低线

不新建图标库。阶段一列出现有 `icons/` 与代码生成图标（页签关闭、勾选、箭头）在线宽、尺寸、对齐上的不一致。阶段三只修正那些在状态矩阵里看得见的问题。

新图标沿用现有约定：主题模块旁边的 `icons/*.svg`，按 token 着色，按所在屏幕的像素比重画。

动效只核对已经存在的 Toast 进出场、以及本版为状态反馈所做的过渡。时长来自 token，并尊重 `reduced_motion`。

验收：状态矩阵里的图标在浅色和深色下都看得见，禁用态不露出未着色的底。Toast 在 `reduced_motion` 下无动画且仍然出现和消失。

### VF-12 兼容

- 不增删 `psi6.api.STABLE` 的名字。
- 不删除、不重命名 `Tokens` 字段。新字段有默认值。
- 控件公开方法和构造参数保持可调用。新增可选参数可以，改变参数含义不行。
- 焦点环默认值是唯一的默认行为变化，必须有迁移说明和测试。
- 自定义主题若只覆盖了部分颜色，在新的推导规则下外观可以更完整，但不得因为新字段缺失而启动失败。
- 六套非旗舰内置主题仍能 `python -m psi6 theme <名称> --check` 加载。它们的审美不在本版重做；若冻结旗舰色板时顺带改坏了某套皮肤的对比度，修到诊断恢复，不借机重画该皮肤。

## 6. 阶段与门禁

四个阶段顺序执行。前一阶段的门禁记录没有写下来，后一阶段不开工。

### 阶段一 · 视觉审计

目的：看清现在的窗口，而不是再读一遍源码。

工作：

- 在 Windows 真实窗口打开 kit 与 gallery 的现有页面，覆盖四种组合。
- 按 VF-05 的控件族记录截图：默认外观、能操作到的状态、一张窄窗口、一张 150%（或本机最接近的高 DPI）。
- 问题清单只记看得见的问题：裁切、对不齐、圆角不一致、边框糊成一片、焦点缺失、悬停看不出、深色表面分不开、整屏卡片化、换主题后颜色停住。
- 每条问题对应到控件和主题组合。功能缺失记到第 2.2 节的后续列表，不记成 0.7.0 缺陷。

门禁：问题清单和改前截图入库。没有这批材料，不写阶段二的具体色值。

2026-11-12 的改前材料已入库：[阶段一审计](audit-0.7.0/findings.md)。阶段二的规范稿已入库：[0.7.0 设计规范](../design/0.7.0/README.md)。稿子还没有审定，仍然不改控件。

### 阶段二 · 设计方案

目的：把 VF-01 到 VF-03 写成可以照着实现的规范。

工作：

- 视觉语言短文。
- token 映射表和拟新增字段（含默认值）。
- 四种组合的尺寸表。
- VF-05 的状态规则：每种状态用哪个 token，而不是每种状态一段 QSS。
- 参考页，标明用哪些现有控件。
- 焦点环的几何规则，明确「外框尺寸不变」。

2026-11-12 的稿在 [docs/design/0.7.0](../design/0.7.0/README.md)：八份规范，六页参考稿覆盖四种组合和宽、中、窄三档，外加空、忙、错误和对话框。token 映射没有新增公开字段，旗舰色值维持现值、尚未冻结。

门禁：规范经过一次阅读审定。审定看的是规范加参考稿加阶段一截图，不是看实现。未审定的规范不能当成开工许可。色值在这一阶段提出，在阶段四才叫冻结。

### 阶段三 · 实现

目的：让窗口符合已审定的规范。

工作顺序：

1. token 与推导、对比度诊断。
2. 焦点环默认值与几何补偿。
3. 全局样式和已有控件按状态规则改。改一个控件族，就在工作台里能看到该族。
4. 工作台与三张参考页。
5. 文档、Skill、迁移说明、检查器对字面色的诊断。

实现时保持公开 API。控件逻辑（排序、增量加载、任务取消语义、配置写入）不因为视觉任务被改写。若视觉实现暴露了功能缺陷，单独记录，能用最小修复解决且有测试的可以修，不能借机做 0.8.0 的功能。

门禁：`pytest`、ruff、mypy 通过；`python -m psi6 check` 对模板和工作台通过；主题 `--check` 对旗舰四种组合和六套既有皮肤通过。这些只是实现门禁，不是发布门禁。

### 阶段四 · 验收

目的：用 VF-09 的材料决定能否称为 0.7.0。

工作：

- 按阶段一的同一批页面重拍。
- 填写对照表：问题、改前、改后、依据的规范条款、是否仍开放。
- 开放项若属于 VF-01 到 VF-12，版本不能发布。
- 通过后更新 CHANGELOG、README 的冻结陈述，以及 ADR 0003 里已经过时的「尚未冻结」句子。
- 把版本号改为 0.7.0 只发生在这一步。

## 8. 后续版本只保留标题

避免 0.7.0 施工时把路线图当成当前迭代。

- **0.8.0 Component Completeness**：补齐第 2.2 节列出的控件能力，优先 `TreeTable`、`PropertyInspector`、表格编辑、菜单与快捷键的统一命令、表单联动。仍然不把 CAD、ETL、投标等业务页放进核心。
- **0.9.0 Agent UI Intelligence**：机器可读的组件知识、页面规则、`visual-check`、按报告修复的回路。设计工作台在那一版才考虑可编辑 token。
- **1.0.0 Production Ready**：稳定承诺、三平台真实 GUI、高 DPI 与多显示器、打包。Python 版本支持在这一版之前单独决策。

## 9. 风险

- **审计被跳过。** 最大的风险是直接改 QSS。阶段门禁就是用来挡这件事的。没有改前截图，阶段三的改动应当停下来补审计，而不是补一张「完成后截图」充数。
- **色值在实现中途反复改。** 阶段二定稿后，实现只修正对比度失败和截图里证明看不清的问题。审美偏好的再次改版回到阶段二，不在控件代码里试色。
- **焦点环默认打开引起下游截图或测试变化。** 这是预期的行为变化。psi6 仓库内测试跟着改；下游应用用 `focus_ring=False` 保持旧外观。不提供静默兼容开关。
- **工作台做成第二个产品。** 工作台只为展示和验收。token 编辑器、代码生成器、在线主题商店都不属于本版。
- **高 DPI 只能在一台 Windows 上看。** 验收记录写明机器和缩放。看不到的缩放保持「未验证」，不写进 README 的已验证列表。
- **非旗舰主题被旗舰色板连带改坏。** VF-12 要求它们仍能通过对比度检查。视觉上只要求可用，不要求和旗舰一样精致。
