# 08 设计决策与未决问题

状态：阶段二设计稿。这里是其他文档发生冲突时的对照表。未决项没有被写成色值或新 API。

本阶段没有修改 `src/psi6` 的控件、主题和 QSS。参考稿是独立绘制的设计图，使用现有 token 的现值。

## 决策

### D1 视觉基础，不是新控件清单

0.7 整理已经存在的窗口。日期选择、树表、图表、向导、通知中心仍属于后续版本。参考页只用现在有的控件名。

依据：`psi6.ui.__all__` 与阶段一「没有当成缺陷」的那一节。

### D2 两个轴保持独立

`Theme.base` 只改颜色，`Theme.style` 只改尺寸，`App.density` 只在运行时选择尺寸预设。不新增 `style` 取值，不把紧凑做成第三种配色。

依据：`docs/adr/0003-workbench.md` 与 `tokens.py` 的度量拆分。参考稿里「浅色紧凑 / 宽」同时存在，用来证明宽布局可以配紧凑尺寸。

### D3 不新增公开 token 字段

语义表是别名。焦点环外移、阅读列 720、控件间距至少 8，都是布局和绘制规则。若实现时发现必须新增字段，先回到本文件修订，不在 QSS 里临时加名字。

依据：阶段二约束，以及现有字段已经覆盖窗口、表面、文字、主色、焦点、危险色和三档间距。

### D4 色值按角色冻结：中性灰白，蕨绿只做强调

默认浅色和深色不再使用蓝或紫。画布是纯白或炭黑，侧栏、悬停和输入槽是中性灰，不把绿色铺进面板。主操作、焦点、链接和用户气泡是蕨绿。成功是橄榄，信息是暖褐，警告是琥珀，危险是红。对比度见 [03](03-design-tokens.md)。

焦点色对主色填充只有 1.52 / 1.39。处理方式仍是把环画到父级表面上。

可选主题不跟随这套主色：黑曜石保持靛紫，松绿、黄铜、极简保持各自的主色。

依据：默认主题需要现代化并且明确排除蓝、紫。`contrast_notes` 对浅色、深色和全部内置主题没有诊断。

### D5 焦点环默认关闭

`App` 的 `focus_ring` 默认 `False`。有的控件上环很难看，不适合作为每个人打开应用就看到的样子。需要对照键盘焦点时传 `True`，或调用 `set_focus_ring(True)`。`build_stylesheet` 与按钮样式函数的默认仍是打开，单独预览和主题断言不受影响。组件目录为展示状态矩阵显式打开。

依据：默认打开之后，勾选、单选和一部分自绘控件上的环会裁切或残留。样例工作台因此不再强制打开。

### D6 状态分通道

悬停改填充。焦点用外侧环。错误替换控件边为 `color_danger`，并在控件下写 `color_danger` 的句子。禁用使用 `color_bg` + `color_border_subtle` + `color_disabled`，不使用主色。选中使用 `color_selected` 加主色标记。

因此输入框的焦点不再是一圈替换边框的粗蓝线，表单错误不再只有一行红字、框仍是灰的。

依据：`apply.py` 里输入焦点把 `border` 设为 `color_focus`，按钮焦点同样替换边；表单页 `formlab.png` 的错误没有红框。

### D7 次按钮是有边的实心控件

次按钮填充 `color_elevated`，边 `color_border`，字 `color_text`。禁用才使用 `color_disabled`。浏览、取消、校验走次按钮，和主按钮成组放置。

依据：`scenes/light/file-index.png` 里取消靠右、浏览被省略；`formlab.png` 里校验接近禁用。

### D8 页面先占满区域

设置用 720 阅读列和贴底动作条。文件索引用工具栏、筛选行和撑满的表。任务用参数列、撑满的日志和贴底的开始/取消。对话用下沉记录区和贴底输入条。工作台三栏同一表面。空状态属于宿主区域。

画廊首页的 `ToolTile` 网格只用于启动器。

依据：阶段一 V-01、V-07、V-08、V-10，以及 Windows 设置、VS Code、文件管理器的结构。参考稿是这几条的可视化。

### D9 窄窗口用同一条 760

宽度小于 760：侧栏变图标轨，工具栏右组进入 `more`，表单在内容宽小于 560 时上下堆叠，工作台按最小栏宽收起。页面中间区域滚动。按钮文字不省略。

参考应用最小窗口 640×420，保证这条阈值拖得到。`density=auto` 在同一阈值切换尺寸，布局切换不依赖尺寸是否已经切换。所以「浅色现代 + 窄」仍然使用现代度量，同时使用窄布局。

依据：阶段一窄图在放开最小尺寸后才得到，且 `data.png` 被裁切。

### D10 圆角只有三档，阴影只给浮起的卡片

页内表面默认不加投影。`Card(elevated=True)` 是唯一例外：模糊 16、向下 2px，不新增阴影 token。`Panel`、对话框、Toast 仍然只有 1px 边。文件索引、设置、任务页不用卡片墙。

控件与容器用 `radius`，复选框用 `radius - 2`，自绘窗口用 `window_radius`。去掉样式表里的 `radius + 4` 和写死半径。除了浮起的 `Card`，页内无投影。模态用已有遮罩色。

依据：`0.7.0-visual-foundation.md` 对 `apply.py` 魔法半径的记录，以及「不以阴影和圆角作为现代化手段」。

### D11 导航项必须分得开

每个目的地不同图标。选中项有主色竖条。不渲染空标题项。主题切换列出四种旗舰组合，外加跟随系统；「紧凑」不是第三种底色。

依据：组件目录每一张图底部的空图标，以及画廊只有「浅色 / 深色 / 紧凑」。

### D12 组件状态矩阵是固定列宽的目录

列宽按内容，不把某一列拉到窗口右缘。族按按钮、输入、选择、导航、数据、反馈分组。表格、页签、横幅进入矩阵。横幅的关闭是安静的图标按钮。

依据：`kit/*/states.png` 的拉散列，以及 `feedback.png` 上比警告更抢的蓝色关闭块。

### D13 参考稿不是实现，也不是验收

`scripts/design_reference_070.py` 用 `Tokens` 现值离屏绘制，不经过 `apply.py`。它用来让下一阶段看见版式和状态通道。控件是否达标，仍要在真实窗口里用阶段四的前后对照验收。

## 未决

这些问题不许在实现时擅自填上。

1. 深色 `color_danger` 是否要降低粉感。对比度已过，等真实窗口。未决期间禁止更换该色值。
2. Windows 显示缩放 125%、150%、175%、200%，以及 macOS、Linux 的图形验收没有做。参考稿是 100% 逻辑像素。`QT_SCALE_FACTOR` 不能写成系统缩放已通过。
3. 阶段一的悬停和按下是 `psi6State` 模拟的。本规范写了悬停填充规则，指针下的实际效果在阶段四确认。
4. 既有六套皮肤不重做。它们的对比度若失败，只修到通过 `contrast_notes`，不套用旗舰参考稿的版式重绘。
5. 焦点环改为默认开启会影响已有应用。迁移说明的措辞在实现阶段写，不在本阶段改代码。
6. `set_style` 的字面色是否在严格模式下报警，留给实现阶段的检查器。默认检查保持不失败。
7. 选中表面在深色侧栏上很接近底色。本规范用主色竖条补强。若阶段四认为竖条仍不够，再讨论选中色，不在实现中途换一个蓝。
8. 底栏在任务页按钮居左、在设置页按钮居右。这是两种页面的阅读顺序，不是 `ActionBar` 的两种新风格名。实现时用现有的左右槽，不新增样式枚举。

## 给实现阶段的顺序

审定本目录之前，不按本文改控件。审定之后的顺序仍是需求计划里的：token 诊断、焦点几何与默认值、控件状态、参考页、文档与迁移。公开 API 的名字保持不变。
